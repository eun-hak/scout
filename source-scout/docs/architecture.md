# Source Scout 설계

## 설계 원칙

- 발견과 사용을 분리한다. URL을 발견했다고 사용할 권리가 생기지 않는다.
- 원작자와 권리 상태가 확인되지 않은 후보는 제작 승인 상태로 바꿀 수 없다.
- 플랫폼별 수집기는 핵심 데이터 모델과 분리한다.
- 자동 점수는 의사결정 보조 수단이며 최종 판단은 사람이 한다.
- 원본 미디어 다운로드 기능은 권리 확인 이후 별도 모듈로 둔다.
- 대시보드와 데이터 API는 단일 관리자 로그인 세션으로 보호한다.

## 인증

- 관리자 아이디와 비밀번호는 `SOURCE_SCOUT_USERNAME`, `SOURCE_SCOUT_PASSWORD` 환경변수에서만 읽는다.
- 세션은 HMAC-SHA256으로 서명하며 서버에는 별도 세션 레코드를 저장하지 않는다.
- 쿠키에는 `HttpOnly`, `SameSite=Lax`, HTTPS 환경의 `Secure` 속성을 사용한다.
- 기본 세션 수명은 24시간이며 최소 허용값은 12시간이다.
- 운영 환경의 서명 키는 `SOURCE_SCOUT_SESSION_SECRET`에 32자 이상으로 설정한다.
- 운영 데이터베이스는 `SOURCE_SCOUT_DATA_DIR`을 통해 코드 배포 경로와 분리한다.

## 처리 흐름

```text
수동 등록 / 브라우저 확장 / 공식 API / 허용된 피드
                │
                ▼
          후보 정규화·중복 검사
                │
                ▼
       콘텐츠 적합도 + 위험도 평가
                │
                ▼
        원작자·사용 권리 확인 대기
                │
                ▼
       검토 승인 → 대본 제작 파이프라인
```

## 핵심 상태

- `new`: 새 후보
- `reviewing`: 콘텐츠 검토 중
- `permission_needed`: 원작자 허락 필요
- `approved`: 권리와 소재 검토 완료
- `rejected`: 사용하지 않음

권리 상태는 작업 상태와 별도로 관리합니다.

- `unknown`: 미확인
- `contact_needed`: 원작자 연락 필요
- `requested`: 허락 요청 완료
- `permitted`: 상업적 편집·게시 허락 확보
- `licensed`: 라이선스 확보
- `public_domain`: 퍼블릭 도메인 확인
- `denied`: 사용 불가

## 점수 모델

각 항목은 1~5점입니다.

| 항목 | 가중치 | 의미 |
|---|---:|---|
| 첫 장면 집중도 | 25% | 스크롤을 멈추게 할 시각적 사건 |
| 설명 가능성 | 25% | 원리·맥락·검증 등 새 정보 추가 가능성 |
| 한국 시청자 신선도 | 20% | 국내에서 덜 알려진 소재인지 |
| 편집 적합성 | 15% | 15~45초 서사로 구성 가능한지 |
| 원작자 추적성 | 15% | 최초 게시자와 권리자를 확인하기 쉬운지 |

위험도 1점은 위험이 낮고 5점은 높습니다. 종합점수에서 `(위험도 - 1) × 5`를 차감합니다.

`approved`는 권리 상태가 `permitted`, `licensed`, `public_domain` 중 하나일 때만 허용됩니다.

현재 자동 제안은 페이지에 공개된 제목과 설명의 키워드를 이용하는 보수적인 규칙 기반 분석입니다. 영상 프레임을 직접 분석하지 않으며, 화면에는 자동 제안 근거를 함께 표시합니다. 향후 영상 이해 모델은 `analyzer.py` 인터페이스 뒤에 추가합니다.

## 향후 모듈 경계

```text
collectors/       공식 API, RSS, 북마클릿 입력
normalizers/      URL과 계정명 정규화
analyzers/        자막, 장면, 중복, 적합도 분석
rights/           허락 요청과 증빙 관리
handoff/          대본·TTS·편집 파이프라인 전달
```
